# DeepSeek Harness Mobile

The [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) agent, running **on your Android phone** — a mobile chat UI over a real on-device agent that reads files, runs commands, and edits code. No cloud round-trip: the agent, your files, and your model key all stay on the device.

English | [中文](README.zh.md)

> **Heads-up — this is not a native app.** You launch it as a **web page** in the phone's browser; the agent itself runs under [Termux](https://termux.dev/) on the device. There is no standalone APK — Termux must stay running for the agent to be reachable.

> **About this repository.** This is a fork of the original *DeepSeek Harness Mobile* distribution, rebuilt around a reproducible **build/patch pipeline**: every tarball in `install/` is now generated by `build/build.js` from the stock upstream `0.2.1-alpha.5` packages plus a small per-package patch in `build/patches/` — no more hand-built binaries. The mobile behaviors (single-column shell, optional native deps, filesystem fallbacks, picker hardening) carry over from the original fork, ported to the 0.2.1-alpha.5 generation of the harness. See [build/README.md](build/README.md).

## What it is

DeepSeek Harness is an on-device AI coding agent. This project is its **Android distribution**: the agent core runs under [Termux](https://termux.dev/) on the phone, and you talk to it from the phone's browser at `http://127.0.0.1:3080`. It tracks upstream at **0.2.1-alpha.5** — the same generation as the desktop harness.

On a phone viewport (≤ 767 px) the web UI renders a single-column mobile shell — the sidebar and the right-hand panel slide in as drawers — instead of the desktop three-column grid. The conversation fills the screen; the composer sits pinned at the bottom.

## Why on-device

- **Privacy** — your files and model API key never leave the phone.
- **No cloud server** — the agent is local, so there is no subscription or always-on server to trust.
- **Loopback-only** — the web RPC is unauthenticated by design, but it binds `127.0.0.1`, which the phone browser shares on the device loopback; nothing listens on the LAN.

## Requirements

- An **arm64-v8a** Android phone with **8 GB+ RAM** (a flagship SoC runs everything comfortably — the core is pure JavaScript plus the builtin `node:sqlite`).
- [Termux](https://termux.dev/) installed from **F-Droid** (the Play Store build is stale).

## Install

1. Install the base packages:

   ```sh
   pkg update -y && pkg upgrade -y
   pkg install -y nodejs-lts git bash
   ```

2. Copy this repository's `install/` folder onto the phone, then run the patcher:

   ```sh
   cd install
   bash install.sh
   ```

   The patcher installs the pinned CLI (`@deepseek-ai/dsh@0.2.1-alpha.5`) plus **11 mobile patch packages** — the mobile shell, the Android/Termux runtime patches, and the directory-picker hardening — as local tarballs, then verifies every override took effect. Native-addon build warnings (koffi/sharp/node-pty) during install are **expected and harmless**.

## Run

```sh
export DSH_HOME="$HOME/.dsh"
export DSH_PERMISSION_MODE=danger-full-access
export DSH_TELEMETRY_DISABLED=1
node --expose-internals \
  /data/data/com.termux/files/usr/lib/node_modules/@deepseek-ai/dsh/lib/bin.js \
  web --port 3080
```

Open `http://127.0.0.1:3080` in the phone browser, enter your model API key on the Models page, create a session, and send a command — for example, *"run a bash command that prints the device model"*.

## Security

- **Loopback only.** The web RPC is a remote code execution surface by design and is **unauthenticated**. It binds `127.0.0.1`, shared with the phone browser on the device loopback, so nothing listens on the LAN. Do not add `--host 0.0.0.0`.
- **`DSH_PERMISSION_MODE=danger-full-access`.** Android has no `bwrap`/Landlock/Seatbelt/ACL sandbox backend, so the sandbox seam fails closed. The launcher opts into running unconfined — treat the agent like shell access.
- **`DSH_TELEMETRY_DISABLED=1`** keeps session telemetry off by default.

## What this project patches vs. upstream, and why

This distribution is a small, self-contained **patch set** over the stock `@deepseek-ai/dsh-*` packages at `0.2.1-alpha.5`, so the agent installs and runs on Android/Termux. Every patch exists for a concrete Android reason:

- **Mobile single-column shell** (`client-ui-layout`) — at ≤ 767 px the frame swaps the three-column grid for `MobileFrame`: a top bar (hamburger + details toggles), the conversation, and two always-mounted slide-over drawers (sidebar, right-hand panel) reusing the same layout store — no mobile-specific state, side content keeps its state across drawer close.
- **Optional native addons** (`attachment-local`, `fs-local`, `session-persistence-jsonl`, `host-directory-picker-native`, `subprocess-local`, `sandbox-local`) — `sharp`, `koffi`, `node-pty` and `dsh-sandbox-windows-acl` move to `optionalDependencies` and lazy-load, so `npm install -g` succeeds on Termux where no glibc prebuilt exists.
- **Android filesystem fallbacks** (`attachment-local`, `fs-local`, `session-persistence-jsonl`) — Android's FUSE/sdcardfs/SELinux rejects `link(2)` hard links, so attachments, the write tool and session logs fall back to `rename()` / `copyFile(COPYFILE_EXCL)` instead of failing.
- **Directory-listing hardening** (`host-directory-picker-browse`, `client-ui-directory-picker-browse`) — sdcardfs listings can stall forever: the host side runs them under a hard deadline with a windowed listing, and the browser side shows a one-tap **Retry** when a listing fails.
- **Android sandbox messaging** (`sandbox`, `sandbox-local`) — no sandbox backend exists on Android; the seam now says so explicitly ("Android has no sandbox backend") and the Windows-ACL module loads lazily with the platform threaded through.
- **Process inspection on Android** (`subprocess-local`) — Android is treated as Linux for process inspection, and the spawn-helper bootstrap no longer dies on a missing `node-pty` (guarded module resolution).
- **Termux shell resolution** (`terminal-bash`) — the terminal resolves its shell to `$PREFIX/bin/bash` on Android (`/bin/bash` does not exist in Termux).
- **HMR needs `--expose-internals`** — the launcher passes it so the HMR service mounts on Android.
- **No more `client-modules` patch** — upstream `0.2.1-alpha.5` already serves plugin bundles with immutable cache-control, so the stock package (installed via the CLI's exact pin) is used as-is.

## Rebuilding the patch set

The tarballs in `install/` are generated, not hand-built: `build/build.js` unpacks each stock `0.2.1-alpha.5` package, applies `build/patches/<name>.patch`, verifies (version, optional deps, patch markers, syntax), and repacks. See [build/README.md](build/README.md).

## Keeping the agent alive

- `termux-wake-lock` (from `termux-api`) keeps the CPU awake.
- Run inside `tmux` so the agent survives an accidental Terminal swipe-away: `tmux` → `dsh-web` → `Ctrl-b d` to detach, `tmux attach` to return.
